# Honest completion boundaries

The runnable service, source snapshots, evaluation scenarios, command-line tools,
report, runbook, incident evidence and demonstration scripts are included. Several
aspects should not be represented as fully proven production capability:

1. The CBIC-authored tariff is the 2022 edition obtained through a mirror after
   CBIC's host failed. GRI is an authoritative WCO substitute rather than CBIC's
   download. The DGFT snapshot has not been checked against every later amendment.
   Faculty corpus confirmation/current legal-policy confirmation remains pending.
2. The default provider is a delayed deterministic stub. The real-model adapter
   is implemented but no credentialed live LLM evaluation was available. Reported
   v1/v2 changes measure a prompt/planner ablation, not isolated real-LLM prompt
   performance. Automatic quality measures are deterministic evidence proxies.
3. Recognition uses an explicit bounded article lexicon and deterministic planner.
   It handles the reference and published scenarios; it is not an unconstrained
   general trade classifier. Unrecognised goods ask for clarification or escalate.
   GRI 2/3 unresolved composites escalate; the service does not autonomously decide
   essential character or use 3(c) to resolve difficult legal disputes.
4. Four-digit recommendations outside the narrowly supported flask split are
   heading-level proposals, not completed eight-digit declarations. No filing,
   duty calculation, document issuance or country sanctions decision occurs.
5. Injection/toxicity checks are baseline NFKC+regex screening and a restricted
   tool surface, not robust multilingual safety classifiers. They have false
   negatives/positives. An authenticated gateway, retention policy and durable
   multi-node Redis are future deployment work.
6. Cost uses configured prices and reported usage. Stub actual cost is $0; token
   counts there are explicitly estimated. An absent live provider usage field
   cannot establish exact token usage. No dollar savings for a paid model are
   invented from the free stub measurements.
7. Load results are short, closed-workload runs in a small cloud machine with
   VFS storage and CPU/memory constraints. They are reproducible development
   measurements, not a production capacity certification. Read results/ and the
   report for actual successful/failed tests and sample counts.
8. All services are declared under Compose. Full monitoring-stack simultaneous
   startup initially exceeded this environment's 7.9 GB root filesystem with VFS.
   Core-service tests and any subsequent monitoring checks are reported separately.
   A clean full-stack run must be rehearsed on Docker Desktop/overlay storage
   with adequate disk; no successful full-stack startup is claimed without evidence.
9. A GitHub URL, student identities, evaluator sign-off and live presentation/viva
   cannot be manufactured. Fill docs/TEAM.md, push the included source to GitHub,
   confirm the corpus with the evaluator and perform the documented rehearsal.
